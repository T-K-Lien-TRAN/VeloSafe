# VéloSafe — Flutter MVP

A working **prototype** of a bicycle reporting and route comparison app using FLutter and Supabase. Read Tutorial for Flutter here if you want: https://docs.flutter.dev/learn and Supabase: https://supabase.com/

## Prerequisites

- Flutter 3.32+ / Dart 3.8+, a supported Android/iOS/Web target, JDK 21 for Android MapLibre builds.
- Internet connection for map tiles.
- Android and iOS are generated by Flutter

## 1. Generate platform folders, install packages, and run

```bash
flutter create velosafe
cd velosafe
flutter pub get
flutter doctor
flutter run -d chrome
```

**Android:** Inside `android/app/src/main/AndroidManifest.xml`, add the permissions
from `docs/android_permissions.xml` directly under `<manifest>` and before
`<application>`. Do not paste them into `<application>`.

**iOS:** Add the location usage text in `docs/ios_info_plist_permissions.xml`
to the `<dict>` in `ios/Runner/Info.plist`. iOS requires macOS/Xcode for building.

Use `flutter devices` to select an Android phone. `maplibre_gl` does not support
Flutter Linux desktop; run Android/iOS or a Web browser instead.

## 2. Demo mode (default)

No keys required. The app loads actual OpenFreeMap map tiles and **four fictional**
nearby hazards positioned around Nice. Report, confirm, and resolve hazards
in memory. All reports disappear when the app restarts.

The route view draws a **grey straight-line preview only**, clearly marked
**NOT a navigable route**. This avoids fabricating a cycling route.

## 3. Supabase mode (persist reports)

1. Create a Supabase project at https://supabase.com/.
2. Enable **Authentication > Providers > Anonymous sign-ins**.
3. Run `sql/001_hazards.sql` in the SQL editor (on a fresh project).
4. Enable Realtime replication for the public `hazards` table by running the
   commented `alter publication` command once or using the dashboard.
5. Run:

```bash
flutter run \
  --dart-define=SUPABASE_URL=https://YOUR_PROJECT.supabase.co \
  --dart-define=SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
```

Only publishable keys belong in a client application. Never use a Supabase secret
or service role key on mobile. The database uses RLS and anonymous accounts.
Anonymous accounts are device/session-specific and do not prove personhood.

Remote mode shows **only reports actually in your Supabase database**.
The sample reports are intentionally not uploaded.

## 4. OpenRouteService (bike routes)

For a **development-only** Android test, obtain an ORS API key and run:

```bash
flutter run --dart-define=ORS_API_KEY=YOUR_ORS_KEY
```

The ORS key in `--dart-define` is **not secret inside a built app**. Do NOT use
this configuration for a publicly distributed build.

For production, set up a server endpoint that accepts this POST body:

```json
{
  "coordinates": [[7.2620, 43.7102], [7.2700, 43.6979]],
  "alternative_routes": {"target_count": 2, "share_factor": 0.6, "weight_factor": 1.5}
}
```

It should pass that body to the ORS endpoint
`POST https://api.openrouteservice.org/v2/directions/cycling-regular/geojson`,
add the secret ORS API key server-side, and return the ORS GeoJSON response.
Add rate limiting, authentication/quotas, input validation and error handling.
Start Flutter with `--dart-define=ROUTING_API_URL=https://YOUR_HOST/route`.

The mobile app retries without alternative routes for some 4xx errors.
With only one candidate it cannot actually choose a safer route, but it
can score that route against reported hazards. With multiple candidates it
chooses the route with the highest report-based score (duration breaks ties).

## 5. Verify

```bash
flutter analyze
flutter test
```

Tests cover the Safety Score, date/status filtering, and proximity to route.

The implementation follows the published APIs of [MapLibre Flutter](https://pub.dev/packages/maplibre_gl), [Geolocator](https://pub.dev/packages/geolocator), and [Supabase Flutter](https://supabase.com/docs/guides/getting-started/quickstarts/flutter).

## 6. Recommended development order

First, launch the app and verify that OpenFreeMap displays correctly. Next, test creating a hazard, opening its details, and viewing the calculated Safety Score. Once these features work, connect Supabase for persistent reporting and OpenRouteService for real bicycle routes.

This approach lets you debug one component at a time rather than dealing with maps, GPS, authentication, and routing errors simultaneously.

## 7. Limitations

- The Safety Score `max(0, 100 - 2*low - 5*moderate - 10*high)` is experimental,
  not a validated safety metric.
- Map marker circles are colored by severity; full custom marker icons are used
  in the detail view, not the map itself.
- There is no turn-by-turn navigation yet; Start ride is deliberately disabled.
- You must use a backend proxy before deploying with ORS keys.
- Abuse prevention, moderation, privacy review, database scale and better
  map matching are out of scope for this initial MVP.

### 10. API keys:

For **VéloSafe Flutter application**, we need two API keys

1. **`SUPABASE_PUBLISHABLE_KEY`** — Connects VéloSafe to the Supabase database to save and retrieve hazard reports.
2. **`ORS_API_KEY`** — Connects VéloSafe to OpenRouteService to calculate real bicycle routes.

Both services offer free options for development.

## 1. Get SUPABASE_PUBLISHABLE_KEY

**Official website:** https://supabase.com/dashboard

### Step 1 — Create a Supabase account

1. Open https://supabase.com/dashboard.
2. Click **Sign in** or **Start your project**.
3. Sign in with GitHub or your email.
4. Click **New project**.
5. Enter:
   - Project name: `VeloSafe`
   - Database password: Choose a strong password.
   - Region: Choose a nearby European region.
6. Click **Create new project**.

### Step 2 — Find your API key

Once your project is ready:

1. Open your VéloSafe project.
2. Go to **Project Settings → API Keys**.
3. Find **Publishable key**.
4. Copy the key.

It looks like:

```text
sb_publishable_xxxxxxxxxxxxxxxxxxxxx
```

If your project has only legacy keys, you may need to create the new publishable key first.

### Step 3 — Find SUPABASE_URL

In your Supabase project, click **Connect** to find your project URL.

It looks like:

```text
https://abcdefghijk.supabase.co
```

You now have:

```bash
SUPABASE_URL=https://abcdefghijk.supabase.co
SUPABASE_PUBLISHABLE_KEY=sb_publishable_xxxxxxxxx
```

**Important:** Use the publishable key, not the `secret` or `service_role` key. Enable Row Level Security (RLS) on your database tables.

Source: [Supabase — API Keys documentation](https://supabase.com/docs/guides/getting-started/api-keys).

---

## 2. Get ORS_API_KEY (OpenRouteService)

**Official website:** https://openrouteservice.org/

### Step 1 — Create an account

1. Visit https://openrouteservice.org/.
2. Click **Sign Up**.
3. Register an account.
4. Confirm your email address if requested.
5. Log in.

### Step 2 — Find your API key

Open:

https://openrouteservice.org/dev/

In the developer dashboard:

1. Open the **API Key** section.
2. Find **Basic Key**.
3. Click **Copy**.

Since the 2025 account-system migration, the dashboard normally provides a Basic Key automatically. You generally do not need to create a separate token.

Source: [OpenRouteService — API key system update, March 17, 2025](https://ask.openrouteservice.org/t/new-ors-account-site/7115).

### Step 3 — Use the key

Your ORS key may look like a long JWT-style token beginning with `eyJ`. This is normal for keys issued under the newer account system.

You now have:

```bash
ORS_API_KEY=YOUR_OPENROUTESERVICE_KEY
```

Source: [OpenRouteService — Official API FAQ](https://giscience.github.io/openrouteservice/v9.10.0/frequently-asked-questions).

## 3. Run VéloSafe with both keys

Open your Ubuntu terminal:

```bash
cd velosafe
```

Run:

```bash
flutter run -d chrome \
  --dart-define=SUPABASE_URL=https://YOUR_PROJECT.supabase.co \
  --dart-define=SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY \
  --dart-define=ORS_API_KEY=YOUR_ORS_API_KEY
```

Replace all three placeholders with your actual values.

### Example

```bash
flutter run -d chrome \
  --dart-define=SUPABASE_URL=https://abcdefghijk.supabase.co \
  --dart-define=SUPABASE_PUBLISHABLE_KEY=sb_publishable_example123 \
  --dart-define=ORS_API_KEY=example_ors_key
```

These values are examples, not valid credentials.

**Security warning:** This method is suitable only for local ORS testing. Flutter's `--dart-define` does not securely hide secrets in compiled web or mobile applications. OpenRouteService explicitly recommends making API requests through your backend so that your personal key is not exposed.

For a publicly distributed VéloSafe application, move OpenRouteService calls into a Supabase Edge Function or FastAPI backend.

## 4. What happens after connecting the keys?

| VéloSafe functionality | API required |
|---|---|
| Display OpenFreeMap | No API key |
| Display current GPS location | No API key |
| Search origin address | No API key with your current Photon implementation |
| Search destination address | No API key with your current Photon implementation |
| Calculate real bicycle routes | ORS API key |
| Save hazard reports online | Supabase project |
| Retrieve reported hazards | Supabase project |
| Calculate Safety Score | Dart algorithm + hazard data |
| Compare alternative routes | ORS API + Safety Score algorithm |

Remember that Supabase also needs the database schema and access policies configured before the online reporting features will work.
